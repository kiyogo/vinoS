## 2. Logic Chain

1. **Hardware Transition Soundness**:
   - In AMD64 Long Mode, the transition from CPL 0 to CPL 3 requires setting user segment selectors and using `iretq` with a 5-quadword stack frame: `[SS, RSP, RFLAGS, CS, RIP]`.
   - Observation: Disassembly of `enter_userspace` verifies exact frame layout: SS=`0x33`, RSP=`rsi`, RFLAGS=`0x202` (IF=1), CS=`0x2b`, RIP=`rdi`.
   - Deductions:
     - RPL=3 on CS (`0x2b`) and SS (`0x33`) transitions CPL to 3.
     - Bit 9 of RFLAGS (`0x202`) guarantees interrupts are enabled upon arrival in userspace.
     - `cli` prevents race conditions while constructing the frame.

2. **Zero Information Leakage**:
   - Kernel registers could hold kernel memory addresses, heap structures, or stack pointers.
   - Observation: Disassembly confirms that immediately preceding `iretq`, registers `RAX, RBX, RCX, RDX, RSI, RDI, RBP, R8, R9, R10, R11, R12, R13, R14, R15` are all zeroed using `xor`.
   - Deductions: No kernel pointers or confidential state survive into userspace. RSP is securely replaced from the `iretq` frame.

3. **User Fault Containment Reliability**:
   - Observation: In `arch/x86_64/interrupts.c`, `is_user` evaluates `((context->cs & 3) == 3) || ((context->error_code & 4) != 0)`.
   - Deductions:
     - Any page fault originating from Ring 3 decrements `s_pf_recursion`, logs diagnostics, and invokes `process_exit(cur, -11)` and `schedule()`.
     - Kernel mode faults continue to panic safely via `log_page_fault_panic()`.
     - Non-page-fault exceptions in user mode are caught by `handle_user_exception()` and `default_exception_panic()` and routed to `process_exit(cur, -1)`.
     - Kernel stability is maintained under user-mode faults.

4. **Zero Self-Test Regressions**:
   - Observation: Live QEMU execution shows all subsystems (PMM, VMM address space lifecycle, ELF loader, heap, PIT timer, VFS, socket wait queues, handle tables, and sync stress tests) pass with 0 frame leaks and reach the shell prompt `KOS> `.
   - Deductions: Milestone M3 changes introduced zero regressions to kernel functionality.

## 3. Caveats & Adversarial Findings

1. **Finding 1: Fallback Behavior when User-Faulting Thread Has `cur == NULL || cur->pid <= 1`**:
   - *Observation*: In `arch/x86_64/interrupts.c:276-284`, if a user fault occurs when `cur == NULL`, `process_exit()` is not called and the handler executes `schedule()` then returns. If `cur` has `pid <= 1` (`kernel_process`), `process_exit()` returns early without killing the process.
   - *Blast Radius*: Currently harmless because user mode is not yet entered by PID 0 or PID 1.
   - *Mitigation for M4*: In Milestone M4, ensure that if `(context->cs & 3) == 3` faults while `cur == NULL || cur->pid <= 1`, the kernel halts that thread via `thread_exit(-11)` rather than returning from the ISR.

2. **SMP Context**:
